# Payroll File Submission Failure

## Purpose

Each month PeopleHub, our HR and payroll system, produces the staff payroll file and sends it to PayHub as a bulk payment. If the file is late, rejected or incomplete, around 4,200 colleagues may not be paid on time. This runbook tells the HR Systems on-call analyst how to find and fix the problem, and when to involve Payments Platform.

## When to use this runbook

- The payroll file has not reached PayHub by 14:00 on the submission day (three working days before payday).
- PayHub rejects the file or part of it.
- Totals in the PayHub acknowledgement do not match the PeopleHub payroll report.

## Symptoms and alerts

| Signal | Source |
|---|---|
| `PeopleHubPayrollExportFailed` | PeopleHub job scheduler, emails HR Systems on-call |
| No acknowledgement file in `/outbound/payroll/ack` by 14:30 | SFTP monitor |
| Rejection file `PAYROLL_<date>_REJ.xml` | PayHub bulk intake |
| Payroll team reports totals mismatch | Payroll mailbox |

## Checks

1. In PeopleHub, open the payroll run and confirm its status is "Approved". The export only starts after final approval by the Payroll Manager.
2. Check the export job log in the PeopleHub scheduler for errors, for example missing bank details or invalid sort codes.
3. Confirm the file was written to the outbound folder and transferred:
   ```
   sftp payroll-svc@sftp.hr.internal
   ls -l /outbound/payroll/
   ```
4. Check the file header: record count, total value and value date. The value date must be payday, not the submission date.
5. In PayHub, check the bulk intake screen for the payroll batch reference. Ask Payments Platform if the batch shows "paused" (bulk intake can be paused during database incidents, see RB-001).

## Steps to fix

1. If the export failed on bad records, correct the employee records in PeopleHub, or remove them from the run with Payroll Manager approval and pay them by manual payment later.
2. Re-run the export:
   ```
   phctl payroll export --run <run id> --resend
   ```
   The `--resend` flag keeps the same batch reference so PayHub will reject an accidental duplicate.
3. If the transfer failed, check the SFTP key has not expired and resend the file. Do not rename the file.
4. If PayHub rejected the whole file, read the rejection reason, fix and resend. If it rejected some records, those must be paid separately; never resend the full file.
5. Confirm the acknowledgement totals match the PeopleHub payroll report, then tell the Payroll Manager.
6. POL-007 sets the payroll file cut-off at 16:00 on the day before payday. If the file is at risk of missing it, ask Payments Operations early to arrange priority processing.

## Escalation

| Situation | Contact |
|---|---|
| Not resolved by 16:00 on submission day | HR Systems team lead |
| PayHub intake problem | Payments Platform on-call |
| Risk that staff will not be paid on time | Grace Mensah (HR Director), Daniel Okafor (Head of Payments Operations) |
