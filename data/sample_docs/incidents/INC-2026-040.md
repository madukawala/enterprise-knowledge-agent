# Payment status consumer lag after deployment

## Summary

On Tuesday 27 October 2026 a new release of the Payment Status Service (PSS), version 4.12, was deployed at 12:05. The release changed consumer settings so that each pod fetched far more messages per poll. Processing each batch then took longer than the Kafka poll timeout, so consumers kept being removed from the group and the group kept rebalancing. Very little work got done. Consumer lag on `payments.status` reached about 2.1 million messages before the release was rolled back at 14:30.

This is the third PSS consumer lag incident in the last year, after INC-2026-017 and INC-2026-030. Idempotency keys in PayHub and Helix Mobile again stopped most duplicate payments, but 41 duplicates came through Helix Online, which does not yet send idempotency keys.

## Root cause

Version 4.12 raised the number of records fetched per poll from 500 to 5,000 to improve throughput. It did not change the poll timeout. Under real traffic, each batch took longer than the timeout, so Kafka treated the consumer as dead and moved its partitions to others, which then did the same. Autoscaling made things worse, because each new pod forced another rebalance.

The release passed pre-production tests, which use a much lower message rate. It was deployed to all pods at once. There was no canary step, so the problem hit all traffic immediately. This overlaps with the configuration change pattern in INC-2026-007, INC-2026-027 and INC-2026-043, but the main customer effect was consumer lag.

**Cause category:** Kafka consumer lag in the Payment Status Service (third occurrence, after INC-2026-017 and INC-2026-030).

## Resolution

The release was rolled back to 4.11 using RB-005. The group became stable and the lag cleared within 25 minutes. Payments Operations matched the 41 Helix Online duplicates and refunded them.

## Lessons learned

- Autoscaling helps with real load but makes a rebalance loop worse. It needs a safety stop.
- Idempotency keys keep paying off. Helix Online is now the only channel where duplicates still get through.
- Consumer settings are configuration. They need a canary like any other change.
