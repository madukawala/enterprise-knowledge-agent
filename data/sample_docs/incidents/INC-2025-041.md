# Card payments declined after Network Gateway certificate expired

## Summary

On Wednesday 3 December 2025 the mutual TLS (mTLS) client certificate that CardSwitch uses to connect to the Network Gateway expired at 06:58. From that moment the Network Gateway refused new connections from CardSwitch, and almost every card authorisation was declined. Both CardSwitch sites used the same certificate, so failing over to the secondary site did not help. Service was restored at 09:46 after an emergency certificate was issued and installed.

There was no alert for certificate expiry. The certificate had a one-year lifetime and the renewal reminder was held in the calendar of an engineer who had left the bank.

## Impact

| Measure | Value |
|---|---|
| Duration of customer impact | 06:58 to 09:46 (2 hours 48 minutes) |
| Declined card authorisations | about 214,000 |
| Customers affected | about 131,000 |
| Value of declined transactions | about £9.6 million |
| Channels affected | All debit and credit card payments: point of sale, online and cash machines of other banks |
| Complaints | 4,870 in the following five days |

Helix cash machines kept working because they do not go through the Network Gateway. Mobile transfers and other payments were not affected.

## Root cause

The client certificate was issued in December 2024 with a 12-month validity. Renewal was a manual task with no owner in the Cards Platform team's rota, and the only reminder was a personal calendar entry. No monitoring checked certificate expiry dates on the Network Gateway connection.

It took over an hour to identify the cause because the CardSwitch error was a generic "network unavailable" code, and the on-call engineer first suspected a network fault. The failover attempt cost a further 25 minutes.

**Cause category:** expired or mis-deployed mTLS certificate between CardSwitch and the Network Gateway (first occurrence).

## Resolution

Cards Platform requested an emergency certificate, installed it on both sites and restarted the Network Gateway connectors. The certificate inventory in ARC-006 was updated with the new expiry date.

## Lessons learned

- A single expiring certificate took down card payments at both sites. Having two sites gives no protection if both share the same certificate and the same mistake.
- Critical renewal dates must never sit in one person's calendar.
- Clear error messages save time. A generic "network unavailable" code sent us down the wrong path for an hour.
- Monitoring must be in place before we call this fixed. This was the first of three certificate-related incidents; see INC-2026-015 and INC-2026-035.
